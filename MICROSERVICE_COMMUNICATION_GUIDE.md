# nIAM Microservice Communication & Configuration Guide

> **Audience:** Any organization deploying microservices behind nIAM.
> By the end of this guide you will have two services running: one with
> local JWT verification (zero network calls) and one with hot-path PDP
> decisions (Ping Identity–style, every request contextual).

## 1. Architecture Overview

nIAM supports two communication patterns for microservices. Pick one or
mix both in the same deployment:

```
┌─────────────────────────────────────────────────────────────────────┐
│                        nIAM Platform                                │
│                                                                     │
│  ┌──────────┐    ┌──────────────┐    ┌──────────────────────────┐  │
│  │  nIAM     │    │  nIAM-PDP    │    │  Your Microservice       │  │
│  │  IAM      │◄───│  (Decision   │◄───│  (PEP — Policy           │  │
│  │  Server   │    │   Service)   │    │   Enforcement Point)     │  │
│  │  :4000    │    │  :4200       │    │  :4100 / :4101           │  │
│  └──────────┘    └──────────────┘    └──────────────────────────┘  │
│       │                │                      │                     │
│       │           ┌────┴────┐                 │                     │
│       │           │PostgreSQL│                 │                     │
│       │           │ (Neon)   │                 │                     │
│       │           └─────────┘                 │                     │
│       │                                       │                     │
│  ┌────┴────┐                           ┌──────┴──────┐             │
│  │ MongoDB │                           │ Flow A:     │             │
│  │(Atlas)  │                           │ Local scope │             │
│  └─────────┘                           │ (no PDP)    │             │
│                                        └─────────────┘             │
│                                        ┌─────────────┐             │
│                                        │ Flow B:     │             │
│                                        │ Hot-path PDP│             │
│                                        │ (every req) │             │
│                                        └─────────────┘             │
└─────────────────────────────────────────────────────────────────────┘
```

| Flow | When to use | Network calls per request | Latency |
|------|-------------|--------------------------|---------|
| **A: Local** | Simple services, CRUD, read-heavy | **0** (JWKS cached) | <1ms |
| **B: PDP Hot-Path** | Banking, healthcare, high-risk ops | **1** (to PDP :4200) | 0.5–2ms |

## 2. Prerequisites

Before configuring any microservice, ensure:

| Item | How to get it | Where it lives |
|------|---------------|----------------|
| **nIAM IAM running** | `http://localhost:4000/api/health` | Elysia server |
| **nIAM-PDP running** (Flow B only) | `http://localhost:4200/healthz` | Elysia + PostgreSQL |
| **Service account** | Created in nIAM org dashboard → Service Accounts | MongoDB (per-tenant DB) |
| **Scopes** | Assigned to the service account | MongoDB `scopes` collection |
| **JWT signing keys** | Auto-generated by nIAM (RS256) | JWKS endpoint at `/.well-known/jwks.json` |

### How to create a service account

1. Log into nIAM dashboard → **Service Accounts** → **Add Service Account**
2. Name: `my-service` (becomes `svc_my-service_<random>`)
3. Assign scopes: e.g. `payments:charge`, `payments:refund`, `reports:read`
4. Save — you'll receive:
   - `client_id` — e.g. `svc_payments_45c1d6`
   - `client_secret` — the raw secret (hashed server-side, shown once)
5. **Copy both immediately** — the secret is not shown again

### How to find your org ID

Your org ID is the **database name** nIAM uses for your tenant:
- Check the URL when logged in: `/orgdash/...` → your org context
- Or query: `GET /api/organization/organization` → look for `dbName` field
- Example: `niamTest`, `acme-bank`, `st-marys`

### How to find your JWT issuer

```
Format: http://<niam-host>:4000/t/<your-org-db-name>

Examples:
  http://localhost:4000/t/niamTest
  https://niam.acme-bank.com/t/acme-bank
```

## 3. Flow A — Local Token Verification

**Best for:** CRUD services, read-heavy APIs, internal tools.
**Pattern:** Verify JWT locally, check scopes — zero calls to nIAM or PDP.

### Step 1: Get a token

```bash
# Exchange client credentials for a JWT
curl -X POST http://localhost:4000/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials" \
  -d "client_id=svc_payments_45c1d6" \
  -d "client_secret=YOUR_SECRET_HERE" \
  -d "scope=payments:charge payments:refund"

# Response:
# {
#   "access_token": "eyJhbGciOiJSUzI1NiIs...",
#   "token_type": "Bearer",
#   "expires_in": 600
# }
```

### Step 2: Configure your service

```typescript
// my-service.ts
import { Elysia } from "elysia";
import { makeJwtVerifier } from "./niamMiddleware";

const NIAM_BASE = process.env.NIAM_BASE || "http://localhost:4000";
const SERVICE_SCOPES = ["payments:charge", "payments:refund"];

const app = new Elysia();

// Verify JWT locally (JWKS fetched once, cached, rotated automatically)
const verify = makeJwtVerifier(NIAM_BASE, {
  audience: "my-service",      // optional: validate aud claim
  scopes: SERVICE_SCOPES,       // optional: enforce scope claims
});

app.get("/payments/charge", async ({ request, set }) => {
  const user = await verify(request);
  if (!user) {
    set.status = 401;
    return { error: "unauthorized" };
  }

  // user = { sub: "svc_payments_45c1d6", scope: ["payments:charge"], ... }
  // Request is authenticated. No network calls were made.

  return { status: "charged", by: user.sub };
});

app.listen(4100);
```

### Step 3: Environment variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `NIAM_BASE` | ✅ | `http://localhost:4000` | nIAM IAM server URL |
| `NIAM_AUDIENCE` | ❌ | — | Expected audience claim |
| `NIAM_SCOPES` | ❌ | — | Required scopes (space-separated) |

### How it works

```
Client                    Your Service                   nIAM (cached)
  │                           │                              │
  │  POST /payments/charge    │                              │
  │  Authorization: Bearer eyJ...                            │
  │──────────────────────────▶│                              │
  │                           │                              │
  │                    ┌──────┴──────┐                       │
  │                    │ Extract JWT  │                       │
  │                    │ from header  │                       │
  │                    └──────┬──────┘                       │
  │                           │                              │
  │                    ┌──────┴──────┐    JWKS (cached)      │
  │                    │ Verify RS256│◀──────────────────────┘
  │                    │ signature   │    (fetched once,     │
  │                    └──────┬──────┘     cached 10min)     │
  │                           │                              │
  │                    ┌──────┴──────┐                       │
  │                    │ Check scopes│                       │
  │                    │ in JWT      │                       │
  │                    └──────┬──────┘                       │
  │                           │                              │
  │  200 { status: "charged" }│                              │
  │◀──────────────────────────│                              │
  │                           │                              │
  Total network calls: 0 (after first JWKS fetch)
```

### Full example — with scope check

```typescript
import { makeJwtVerifier } from "./niamMiddleware";

const verify = makeJwtVerifier("http://localhost:4000");

app.get("/reports/summary", async ({ request, set }) => {
  const user = await verify(request, { scopes: ["reports:read"] });
  if (!user) {
    set.status = 401;
    return { error: "unauthorized or insufficient scope" };
  }

  // Fetch report data...
  return { report: "...", generatedBy: user.sub };
});
```

## 4. Flow B — PDP Hot-Path (Ping-Style)

**Best for:** Banking, healthcare, high-risk operations, compliance-heavy APIs.
**Pattern:** Every request goes to the PDP for a contextual decision
(amount checks, time-of-day, trusted context, risk scores).

### Step 1: Create a policy in nIAM

1. Log into nIAM dashboard → **Policy** → **Add Policy**
2. Configure:
   - **Name:** `refund-guard`
   - **Description:** "Controls refund authorization based on amount, time, and context"
   - **Rules:**
     ```
     Rule 1: resource=payments, action=refund
       → deny (if subject.scope NOT contains payments:refund)
       → deny (if no trusted context)

     Rule 2: resource=payments, action=refund
       → permit (if amount <= 10000 AND time between 09:00-17:00)
       → obligation: step_up (if amount > 10000)

     Rule 3: resource=payments, action=refund
       → deny (always — catch-all after-hours or untrusted)
     ```
3. **Enable** the policy
4. Note the policy name: `refund-guard`

### Step 2: Configure trusted context (optional but recommended)

For banking/healthcare, the PDP should only trust context signed by
the gateway (not the client). Create a shared secret:

```bash
# Generate a secret (do this once, store securely)
openssl rand -hex 32
# Example output: a1b2c3d4e5f6...

# Set in your PEP service environment:
# TRUSTED_CONTEXT_SECRET=a1b2c3d4e5f6...
```

### Step 3: Configure your service

```typescript
// payments-service.ts
import { Elysia } from "elysia";
import { makePolicyGuard } from "./niamMiddleware";

const NIAM_BASE = process.env.NIAM_BASE || "http://localhost:4000";
const PDP_URL = process.env.PDP_URL || "http://localhost:4200";
const TRUSTED_CONTEXT_SECRET = process.env.TRUSTED_CONTEXT_SECRET;

const app = new Elysia();

// PDP-backed guard — every request gets a contextual decision
const guard = makePolicyGuard(NIAM_BASE, PDP_URL, {
  fail: "closed",  // "closed" = deny on PDP outage | "open" = allow
  trustedContextSecret: TRUSTED_CONTEXT_SECRET,
});

app.post("/payments/refund", async ({ request, body, set }) => {
  // 1. Verify JWT + get PDP decision
  const decision = await guard(request, {
    resource: "payments",
    action: "refund",
    // Optional: pass additional context for the PDP
    env: {
      amount: body.amount,
      currency: body.currency,
      ip: request.headers.get("x-forwarded-for"),
    },
    // Optional: client-signed context token (for step-up flows)
    contextToken: request.headers.get("x-payment-context"),
  });

  if (!decision) {
    set.status = 401;
    return { error: "unauthorized" };
  }

  // 2. Handle the decision
  if (decision.decision === "deny") {
    set.status = 403;
    return { error: decision.reason || "forbidden" };
  }

  // 3. Handle obligations (e.g., step-up authentication)
  if (decision.obligations?.includes("step_up")) {
    set.status = 403;
    set.headers["WWW-Authenticate"] = 'Bearer error="step_up"';
    return {
      error: "step_up_required",
      message: "High-value refund requires additional authentication",
    };
  }

  // 4. Permit — process the refund
  return { status: "refunded", amount: body.amount, by: decision.subject };
});

app.listen(4101);
```

### Step 4: Environment variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `NIAM_BASE` | ✅ | `http://localhost:4000` | nIAM IAM server URL |
| `PDP_URL` | ✅ | `http://localhost:4200` | nIAM-PDP decision service URL |
| `PDP_TIMEOUT_MS` | ❌ | `2000` | PDP request timeout |
| `PDP_FAIL_MODE` | ❌ | `closed` | `closed` = deny on outage, `open` = allow |
| `TRUSTED_CONTEXT_SECRET` | ❌ | — | HS256 shared secret for trusted context |

### Step 5: Trusted context signing (gateway-side)

The gateway (or your edge service) signs context tokens that the PDP
validates. This prevents clients from spoofing risk scores, amounts,
or time-of-day:

```typescript
// gateway-sign-context.ts
import crypto from "node:crypto";

const SECRET = process.env.TRUSTED_CONTEXT_SECRET;

export function signContext(payload: Record<string, any>): string {
  const header = Buffer.from(JSON.stringify({ alg: "HS256", typ: "JWT" })).toString("base64url");
  const body = Buffer.from(JSON.stringify({
    ...payload,
    iat: Math.floor(Date.now() / 1000),
    exp: Math.floor(Date.now() / 1000) + 300, // 5 min TTL
  })).toString("base64url");
  const sig = crypto.createHmac("sha256", SECRET).update(`${header}.${body}`).digest("base64url");
  return `${header}.${body}.${sig}`;
}

// Usage: sign context before forwarding to PDP-protected service
const contextToken = signContext({
  amount: 15000,
  currency: "USD",
  ip: "10.1.0.5",
  channel: "mobile",
  risk_score: 0.8,
});
```

## 5. Configuration Reference

### Service Account Scopes

Scopes are the coarse-grained permission layer. They're checked both
locally (Flow A) and by the PDP (Flow B).

| Scope pattern | Meaning | Example |
|---------------|---------|---------|
| `<domain>:<action>` | Standard | `payments:charge` |
| `<domain>:*` | All actions on domain | `payments:*` |
| `*` | Super-admin (use sparingly) | `*` |

**How to assign scopes:**
1. nIAM Dashboard → **Service Accounts** → select account → **Scopes**
2. Or via API: `POST /api/scope` with `{ serviceAccountId, scope: "payments:refund" }`

### PDP Policy Rules

Each rule has this structure:

```json
{
  "resource": "payments",
  "action": "refund",
  "effect": "permit",
  "conditions": [
    {
      "attribute": "amount",
      "operator": "lte",
      "value": 10000
    },
    {
      "attribute": "env.time",
      "operator": "time_between",
      "value": ["09:00", "17:00"]
    }
  ],
  "requires_trusted_context": true,
  "obligations": ["step_up"]
}
```

**Available operators:**

| Operator | Input | Description | Example value |
|----------|-------|-------------|---------------|
| `eq` | string | Equals | `"admin"` |
| `neq` | string | Not equals | `"guest"` |
| `in` | list | Is one of | `["admin", "superadmin"]` |
| `not_in` | list | Is NOT one of | `["blocked", "suspended"]` |
| `exists` | none | Attribute exists | — |
| `not_exists` | none | Attribute missing | — |
| `contains` | string | String includes | `"payments"` |
| `matches` | regex | Regex match | `"^svc_.*"` |
| `gt` | number | Greater than | `1000` |
| `gte` | number | Greater or equal | `10000` |
| `lt` | number | Less than | `50000` |
| `lte` | number | Less or equal | `10000` |
| `between` | range | Inclusive range | `[1000, 50000]` |
| `before` | time | Before HH:MM | `"17:00"` |
| `after` | time | After HH:MM | `"09:00"` |
| `time_between` | range | Within time range | `["09:00", "17:00"]` |
| `in_subnet` | CIDR | IP in subnet | `"10.0.0.0/8"` |

**Attribute paths:**

| Path | Source | Example |
|------|--------|---------|
| `subject.sub` | JWT `sub` claim | `svc_payments_45c1d6` |
| `subject.scope` | JWT `scope` claim | `payments:charge payments:refund` |
| `subject.aud` | JWT `aud` claim | `my-service` |
| `resource` | Request resource | `payments` |
| `action` | Request action | `refund` |
| `env.<key>` | Environment object | `env.amount`, `env.time`, `env.ip` |
| `trustedContext` | Gateway-signed context | `true` / `false` |

### Decision Response

```json
{
  "decision": "permit",
  "reason": "permitted by policy 'refund-guard' (payments:refund)",
  "matched_policy": "refund-guard",
  "matched_rule": "payments:refund",
  "policy_version": 2,
  "obligations": ["step_up"],
  "used_trusted_context": true,
  "required_scope": null,
  "source": "pdp"
}
```

| Field | Values | Description |
|-------|--------|-------------|
| `decision` | `permit`, `deny` | Final verdict |
| `reason` | string | Human-readable explanation |
| `matched_policy` | string or null | Which policy matched |
| `matched_rule` | string or null | Which rule matched |
| `obligations` | string[] | Actions the PEP must enforce |
| `used_trusted_context` | boolean | Whether gateway context was accepted |
| `source` | `local`, `pdp`, `pdp_fail_open`, `pdp_fail_closed` | Which engine decided |

## 8. Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `401 Unauthorized` | Token expired or invalid | Get a new token via `/oauth/token` |
| `403 Forbidden` | Insufficient scopes | Add required scopes to the service account |
| `403` + `step_up` obligation | High-risk operation requires re-auth | Implement step-up flow in your PEP |
| PDP returns `503` | PDP unreachable | Check `PDP_URL` env var, verify PDP is running |
| `denied by policy` | PDP policy blocks the request | Check policy rules in nIAM dashboard |
| `implicit deny (no matching policy)` | No policy matches the request | Create a policy for this resource/action |
| `policy decision point unavailable` | PDP timed out | Increase `PDP_TIMEOUT_MS` or switch to `fail: "open"` |
| JWKS fetch fails | nIAM server unreachable | Check `NIAM_BASE` env var |

## Summary: Which Flow When?

| Your service does... | Use Flow | Why |
|----------------------|----------|-----|
| CRUD operations (read/write data) | **A: Local** | Simple, zero latency, no PDP dependency |
| Internal tools, admin panels | **A: Local** | Low risk, speed matters |
| Payment processing | **B: PDP** | Amount/time/risk checks need context |
| Refund authorization | **B: PDP** | Step-up obligations, compliance audit |
| Healthcare data access | **B: PDP** | HIPAA requires per-request audit trail |
| Banking transactions | **B: PDP** | PCI-DSS requires contextual policy |
| Reports / analytics | **A: Local** | Read-only, low risk |
| User provisioning | **A: Local** | Standard CRUD with scope check |

You can **mix both flows** in the same deployment — some routes local,
some PDP-backed. The `makePolicyGuard` and `makeJwtVerifier` are
independent; use whichever each route needs.
